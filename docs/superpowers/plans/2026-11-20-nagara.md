# nagara Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 作業中に全画面タブで流しておく、音と時間帯に反応する水草水槽（海月入り）のブラウザビジュアルを作る。

**Architecture:** 状態更新（純粋なロジック）と描画（Canvas 2D）を分ける。各シーン要素は `update(dt, stimulus)` と `draw(ctx, lighting)` を持つクラスで、`app.ts` のループが時刻→照明、マイク→刺激を計算して全要素に配る。ロジックは Vitest で検証し、描画はブラウザで目視確認する。

**Tech Stack:** Vite（vanilla-ts テンプレート）, TypeScript (strict), Canvas 2D, Web Audio API, Vitest。実行時の外部ライブラリなし。

**Spec:** `docs/superpowers/specs/2026-11-20-nagara-design.md`

## Global Constraints

- ブラウザだけで動く。サーバーなし。実行時依存ライブラリなし（devDependencies は vite, typescript, vitest のみ）
- 目に痛い点滅を出さない：画面に出る明るさ・強度の値は必ず `smooth()` を通す
- 60fps 目標。泡は最大 120、浮遊物は 60、海月は 2〜3 匹
- マイクを拒否・未対応でも、時間帯モードで描画が続く
- 時間帯：朝 5–10 / 昼 10–16 / 夕 16–19 / 夜 19–5。各境目の前後 30 分（計約 1 時間）で線形補間
- URL `?hour=N`（0 ≤ N < 24、小数可）で時刻を上書き
- 画面上の文言は日本語。初回表示「クリックで音に反応させる」
- リポジトリ `0kimuchi0/nagara`、GitHub Pages で公開（`vite.config.ts` の `base: '/nagara/'`）

## Review Focus

1. タブを長時間裏に回して戻る → `dt` が巨大になっても要素が画面外に飛ばない（`clampDt`、Task 6 のテスト）
2. 日付またぎ・夜明けの境目（23.99→0、4.5→5.5）で照明が跳ばない（Task 1 の連続性テスト）
3. ウィンドウのリサイズ／全画面切替 → 海月・水草が新しい範囲に収まる（Task 4・5 の `resize` テスト）
4. 大音量が続く → 泡が上限を超えず、明るさが 1 フレームで急変しない（Task 2 の `smooth`、Task 3 の上限テスト）
5. マイク拒否・`?hour=abc` や `?hour=25` → 時間帯モードで動き続け、不正値は無視（Task 1 の parse テスト、Task 6 の手動確認）

### Task 1: プロジェクト雛形・乱数・時間帯の照明

  - `NIGHT.speed < DAY.speed`、`NIGHT.jellyGlow > DAY.jellyGlow`
  - `parseHourOverride('?hour=20') === 20`、`'?hour=20.5'` → 20.5、`'?hour=abc'` → null、`'?hour=25'` → null、`''` → null
  - `currentHour(new Date(2026,0,1,14,30), null) === 14.5`、override 3 なら 3
- [ ] **Step 3:** `npm test` で失敗を確認
- [ ] **Step 4:** `palette.ts` と `random.ts` を実装。色の値は設計の言葉に合わせる（朝＝淡い緑と水色、昼＝澄んだ青緑で rayIntensity 最大、夕＝橙がかった暖色、夜＝暗い紺と青で speed 0.5 程度・jellyGlow 最大）
- [ ] **Step 5:** `npm test` が通ることを確認
- [ ] **Step 6:** `git init`（未初期化なら）→ `git commit -m "feat: scaffold and time-of-day lighting"`

### Task 2: 音の分析とマイク入力

**Files:**
- Create: `src/audio/analysis.ts`, `src/audio/microphone.ts`
- Test: `src/audio/analysis.test.ts`

**Interfaces:**
- Produces:
  - `interface Levels { low: number; high: number; volume: number }`（各 0〜1）
  - `bandLevels(freq: Uint8Array, sampleRate: number, fftSize: number): Levels` — low は 20–150Hz、high は 2000–8000Hz、volume は全ビンの平均。いずれも /255
  - `smooth(prev: number, target: number, dt: number, attack: number, release: number): number` — 上昇は attack（秒）、下降は release（秒）の時定数による指数追従
  - `class BeatDetector { update(low: number, timeSec: number): boolean }`
  - `startMicrophone(): Promise<MicSource>`、`interface MicSource { read(): Uint8Array; sampleRate: number; fftSize: number; stop(): void }` — fftSize 2048、許可拒否や非対応時は reject

- [ ] **Step 1: 失敗するテストを書く**
  - 全ビン 0 → `{low:0, high:0, volume:0}`。低域ビンだけ 255 → low が 1、high が 0
  - `smooth(0, 1, 1/60, 0.1, 0.5)` は 0 より大きく 0.25 未満（1 フレームで急変しない）。`smooth(1, 0, 1/60, 0.1, 0.5)` の下降幅は上昇幅より小さい
  - BeatDetector：low=0.4 を 2 秒間 60fps で与えても beat なし → 0.9 を与えると true → その 0.1 秒後の 0.9 は false（最小間隔 0.25 秒）→ low が 0.2 以下のときは急増しても false（閾値 0.3）
- [ ] **Step 2:** `npm test` で失敗を確認
- [ ] **Step 3:** 実装。BeatDetector は直近約 1 秒の low の移動平均の 1.4 倍を超え、かつ low > 0.3、かつ前回の拍から 0.25 秒以上経過で true。`microphone.ts` は `getUserMedia({audio:true})` → `AnalyserNode`（`smoothingTimeConstant` 0.6）
- [ ] **Step 4:** `npm test` が通ることを確認
- [ ] **Step 5:** `git commit -m "feat: audio analysis and microphone input"`

### Task 3: 泡と浮遊物

**Files:**
- Create: `src/scene/types.ts`, `src/scene/bubbles.ts`, `src/scene/particles.ts`
- Test: `src/scene/bubbles.test.ts`, `src/scene/particles.test.ts`

**Interfaces:**
- Consumes: `Lighting`, `mulberry32`
- Produces:
  - `interface Bounds { width: number; height: number }`
  - `interface Stimulus { low: number; high: number; volume: number; beat: boolean; speed: number }`（speed は `Lighting.speed`）
  - `interface SceneElement { resize(b: Bounds): void; update(dt: number, s: Stimulus): void; draw(ctx: CanvasRenderingContext2D, l: Lighting): void }`
  - `class Bubbles implements SceneElement { constructor(b: Bounds, rng: () => number); readonly count: number }`、`const MAX_BUBBLES = 120`
  - `class Particles implements SceneElement { constructor(b: Bounds, rng: () => number) }`、`const PARTICLE_COUNT = 60`

- [ ] **Step 1: 失敗するテストを書く**
  - 無音（high 0）で 10 秒間更新 → count は 1 以上 15 以下（ときどき昇る）
  - high=1 で 10 秒更新 → 無音時より多い。どんな入力でも count ≤ 120
  - `beat: true` を 1 フレーム → count が 8 増える（上限まで）
  - 泡は上昇し、y < 0 になったら消える
  - Particles：30 秒更新しても全粒子が bounds 内（端で反対側に回り込む）
- [ ] **Step 2:** 失敗を確認
- [ ] **Step 3:** 実装。湧く頻度は毎秒 0.5 + high×8。拍で底のランダムな 1 点から 8 個まとめて湧く。上昇速度に `speed` を掛ける。描画は半透明の円＋小さなハイライト。浮遊物は volume に応じて明るさ（smooth 済みの値を受け取る前提）
- [ ] **Step 4:** 通ることを確認
- [ ] **Step 5:** `git commit -m "feat: bubbles and floating particles"`

### Task 4: 水草・底・光の筋

**Files:**
- Create: `src/scene/plants.ts`, `src/scene/floor.ts`, `src/scene/lightRays.ts`
- Test: `src/scene/plants.test.ts`, `src/scene/floor.test.ts`

**Interfaces:**
- Consumes: `Bounds`, `Stimulus`, `SceneElement`, `Lighting`, `mulberry32`
- Produces:
  - `class Plants implements SceneElement { constructor(b: Bounds, rng: () => number); tipOffset(i: number): number; readonly count: number }` — 本数は `Math.round(width / 40)`
  - `class Floor implements SceneElement { constructor(b: Bounds, rng: () => number); readonly shapes: FloorShape[] }`、`interface FloorShape { kind: 'rock' | 'wood'; x: number; w: number; h: number }`
  - `class LightRays implements SceneElement { constructor(b: Bounds, rng: () => number) }`

- [ ] **Step 1: 失敗するテストを書く**
  - 同じ時刻・同じ株で、low=1 のときの `|tipOffset|` の最大値は low=0 のときより大きい
  - 根元の x はどれだけ更新しても変わらない
  - `resize({width:1600, ...})` 後、本数が 40 になり、根元がすべて 0〜1600 に収まる
  - Floor：同じ seed なら同じ shapes、違う seed なら違う shapes。shapes はすべて bounds 内
- [ ] **Step 2:** 失敗を確認
- [ ] **Step 3:** 実装。水草は数節の曲線で、揺れは `sin(t·f + phase)` の基本揺れ＋ low に比例するそよぎ（smooth 済み）。先端ほど大きく揺れる。光の筋は上から差す 4〜6 本の半透明の帯。強さは `rayIntensity × (0.6 + 0.4 × volume)`、拍で少しゆらぐ（ゆらぎは smooth で減衰）
- [ ] **Step 4:** 通ることを確認
- [ ] **Step 5:** `git commit -m "feat: plants, floor and light rays"`

### Task 5: 海月

**Files:**
- Create: `src/scene/jellyfish.ts`
- Test: `src/scene/jellyfish.test.ts`

**Interfaces:**
- Consumes: `Bounds`, `Stimulus`, `SceneElement`, `Lighting`
- Produces: `class Jellyfish implements SceneElement { constructor(b: Bounds, rng: () => number); readonly bodies: ReadonlyArray<{ x: number; y: number; pulse: number }> }` — 匹数は width < 600 なら 2、それ以外は 3

- [ ] **Step 1: 失敗するテストを書く**
  - 匹数：width 500 で 2、1200 で 3
  - 拍を 1 回与えると、0.5 秒後の y がその前より小さい（上に進む）
  - 右端に向かう海月は、60 秒更新しても x が 0〜width の範囲内（端で向きを変える）
  - y は常に height の 10%〜70% の範囲内
  - 1600×900 → 800×600 に `resize` した直後、全員が新しい範囲内
- [ ] **Step 2:** 失敗を確認
- [ ] **Step 3:** 実装。傘は半透明の半楕円、触手は数本の揺れる細線。普段は周期約 3 秒で傘を開閉しながらゆっくり上下・左右に漂う。拍で傘を閉じて上向きの速度を加える。描画時の光は `jellyGlow` と volume（smooth 済み）で決める
- [ ] **Step 4:** 通ることを確認
- [ ] **Step 5:** `git commit -m "feat: jellyfish"`

**Interfaces:**
- Consumes: Task 1〜5 のすべて
- Produces: `clampDt(dt: number): number`（上限 0.1 秒、負なら 0）、`startApp(canvas: HTMLCanvasElement): void`

- [ ] **Step 1: 失敗するテストを書く** `clampDt(3600) === 0.1`、`clampDt(-1) === 0`、`clampDt(0.016) === 0.016`
- [ ] **Step 2:** 失敗を確認 → `clampDt` を実装 → 通ることを確認
